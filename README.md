# Equality Ohio: website redesign

Next.js app for the equalityohio.org redesign, prepared by Joseph Carter Group.
It deploys to a **password-gated** Vercel URL and stays `noindex` until launch.
Agent sessions: read `CLAUDE.md` too.

## Architecture

- **Every page is static HTML under `public/`**, answering on its clean URL
  (`public/about/history.html` is `/about/history`). `lib/static-pages.mjs`
  walks `public/` once, and `next.config.mjs` turns that walk into the
  rewrites, the `.html` to clean-URL redirects and the per-page headers. The
  rewrites are `afterFiles`, so a page later ported to `app/<path>/page.js`
  wins automatically (add its URL to `PORTED` when the static file goes).
- **Head and chrome are generated, not hand written.** `npm run pages:build`
  writes three marked regions into every page: the `<head>` metadata from
  `lib/seo.mjs` (title, description, Open Graph, icons, stylesheets, JSON-LD),
  and the header and footer from `lib/chrome.mjs` (skip link, preview ribbon,
  nav, phone help bar, footer). They are real HTML in the served page, so
  navigation works without JavaScript (the phone Menu is served as a link
  to the footer navigation, and becomes the sheet's button when the script
  runs). `public/js/eo-site-template.js` only adds behavior (phone menu,
  dropdowns, help bar, reveal, form validation).
- **One launch switch:** `LAUNCHED` in `lib/site.mjs` controls robots metas,
  canonicals, the preview ribbon and footer credit, `og:site_name`, the gate,
  `X-Robots-Tag` and `/robots.txt`.
- **Design system:** `public/css/eo-brand-tokens.css` holds every brand
  variable (canonical palette from the official logo: purple `#5A3F99`, blue
  `#0093D0`, green `#9FCF67`) and is the only file allowed color literals;
  `eo-site.css` is the component layer; fonts are self-hosted in
  `public/assets/fonts/`. Icons, share cards and responsive images are
  generated by `npm run assets` from EO's own artwork and committed.
- **Security headers:** a Content-Security-Policy with `script-src 'self'` on
  every static page (so no inline scripts or `onclick=` attributes), plus
  `frame-ancestors 'none'`, HSTS, `nosniff` and no `X-Powered-By`.
- **Branded 404:** `pages/404.js`, prerendered with the same header and
  footer.
- **Forms are visual only** (`data-mock="true"`) until the Supabase phase.
  Donations link out to Equality Ohio's live EveryAction (NGP) pages.

## Setup and commands

Node 22. `npm ci`, then:

```
npm run dev            local dev server (behind the gate; password EO2026)
npm run build          production build; must pass before a PR lands
npm run pages:build    regenerate the head, header and footer in every page
npm test               links, redirects and live-sitemap coverage, tokens,
                       generated-region drift, site rules, content freshness
npm run test:e2e       Playwright: axe WCAG 2.1 AA at 390 and 1280, routes,
                       redirects, headers, gate, behavior (run `npm run build`
                       first; it starts `next start` on port 3100 itself)
npm run lint:a11y      the axe audit only
npm run assets         regenerate icons, share cards, images and textures
```

The individual checks inside `npm test` also run alone: `check:links`,
`check:redirects`, `check:tokens`, `check:pages`. CI
(`.github/workflows/ci.yml`) runs `npm test`, the build and the Playwright
suite on every pull request and on `main`. Copy `.env.example` to
`.env.local` for local overrides; the Playwright suite loads the same env
files `next start` does, so a `STAGING_PASSWORD` set there reaches both.
`EO_TODAY` (for `npm test`) is read from the shell only.

## Staging gate

`middleware.js` redirects every request without the preview cookie to
`/gate`; the form posts to `/api/gate`. It is a **soft gate**: it keeps the
design preview out of casual view and out of search, and it is not a
security boundary for anything secret.

- **Password:** the `STAGING_PASSWORD` env var, falling back to `EO2026`.
  Set it on every Vercel environment to rotate; the cookie is an HMAC keyed
  by the password, so a new password signs every browser out.
- **Rate limit:** 10 failed attempts per address per 15 minutes, held in
  memory per server instance. It slows a guesser; it does not stop a
  distributed one.
- **Open paths** (reachable without the cookie): the gate page and its
  script, the gate endpoint, robots, sitemap, manifest and icons
  (`lib/preview-gate-paths.mjs`), plus the real CSS, font, logo, brand,
  share-card and texture files, listed exactly in
  `lib/open-files.generated.mjs` (written by `npm run pages:build`; the
  edge middleware cannot read the disk). A missing file under those
  directories goes to the gate like everything else, including
  `npm run dev`.
- **Post-login redirect:** `from` must be a same-origin path, checked after
  URL parsing too (dot segments can turn `/.//evil.example` into
  `//evil.example`), and never any spelling of the gate itself.
- Once `LAUNCHED` is true the middleware is a pass-through and `/api/gate`
  answers 404.
- Playwright signs in once with `STAGING_PASSWORD` (or the fallback) and
  reuses the cookie. CI keeps no traces (they would record the cookie and
  the password), since its report is uploaded from a public repository.

## Authoring a page

Follow `docs/authoring-conventions.md`: the skeleton, a `PAGES` entry in
`lib/seo.mjs`, then `npm run pages:build`. The full live-site to new-site URL
map, redirects included, is `docs/site-map.md`.

## Before every deploy

```
npm run pages:build    must report every page already up to date
npm test               must pass; read its warnings
npm run build
npm run test:e2e
EO_TODAY=<deploy date> npm test   nothing expires before the deploy lands
```

`npm test` already checks what used to be manual: passed events and expired
`data-expires` content (the 2026 election sections expire after
2026-11-04), live-sitemap coverage, and links. Still by hand: confirm the
BambooHR posting on `/about/jobs-internships` is open, and refresh
`lib/legacy-post-paths.mjs` and the sitemap snapshot
(`node scripts/check-redirects.mjs --fetch`) when EO publishes posts.

## Launch

`docs/launch-checklist.md` lists every staging-only artifact and every launch
blocker, each with its file or command. The core steps:

1. Clear the blockers `npm test` warns about today (links back to
   equalityohio.org, staging-only copy, mock forms). Once `LAUNCHED` is true
   those warnings become failures.
2. Set `LAUNCHED = true` in `lib/site.mjs`, run `npm run pages:build`, then
   `npm test`, `npm run build` and `npm run test:e2e` (all must pass; the
   e2e suite expects `Disallow: /` and `X-Robots-Tag` from any build that is
   not Vercel production, CI and a local `next start` included). Commit the
   regenerated pages and deploy to production. The gate becomes a
   pass-through, `/api/gate` a 404, the ribbon goes, and robots, canonicals
   and the sitemap switch on (production only).
3. In a cleanup PR after launch, delete the gate (`middleware.js`,
   `lib/preview-gate.mjs`, `lib/preview-gate-paths.mjs`,
   `lib/open-files.generated.mjs` and its step in
   `scripts/build-pages.mjs`, `lib/rate-limit.mjs` if unused,
   `app/api/gate/`, `public/gate.html`, `public/js/eo-gate.js`, the gate
   tests) and the `STAGING_PASSWORD` env var.
