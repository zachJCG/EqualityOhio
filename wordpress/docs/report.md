## Phase 1: theme foundation

- `theme.json` is generated from `eo-brand-tokens.css` (35 palette entries, 3 font families with the same ten woff2 files, 1160px layout, no blockGap so WordPress emits no flow-gap rules). `eo-site.css` is byte-identical to the source apart from two texture paths; every WordPress adjustment is in `eo-wp.css`.
- Header, footer, help bar and 404 body are PHP dynamic blocks (`eo/site-header` etc.) rendering the source markup from WordPress menus (five locations), falling back to built-in data. This is the "render the same markup from a menu" option the brief preferred; the core Navigation block was not used.
- The block-theme skip link is unhooked at `init` (it is injected into the template HTML before `wp_enqueue_scripts`), so there is exactly one. Template parts render in `display: contents` wrappers so the sticky header lays out as before.
- `eo-site.js` is the source script with two marked changes: the help bar also watches `.clinic-cta` (core blocks drop bare `data-cta`), and it finds the footer by class when it is not the bar's sibling.
- Footer year is `wp_date('Y')`.

Checks: behavior spec 35/35 (JS-off Menu link to `#footer-nav`, focus trap, Escape, one dropdown at a time, hover open/close, help bar hide/show, error summary, success note, new-tab notes, short-viewport header). axe: 0 violations at 390 and 1280 including the open menu and an open dropdown.
